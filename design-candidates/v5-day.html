I. The night shift

01:20 — 03:00 · four jobs · nobody watching

01:20 daily

memory-index

Everything the day produced gets read back and indexed so tomorrow's agents can find it. The system's short-term memory becomes long-term memory while I sleep.

First job of the day. The day it doesn't run, everything downstream gets slightly dumber.
01:30 daily

harmony-backup

This is the one that told me something was wrong.

A process guardian I wrote failed silently — and a silent guardian is worse than none at all.

It was supposed to stop a worker from multiplying. One night it stopped doing its job without stopping reporting. It kept saying healthy while the worker spawned copies of itself and wrote logs until the disk was full.

I found out because the 01:30 backup had nowhere left to write. I traced it back to the root cause, recovered the machine, and then did the part that actually counts: I wrote the check that catches it next time. That check is fleet-health, and it runs at 06:59 every morning. system-watchdog runs every four hours behind it. Both are loud on purpose now.

I'd rather tell you about the night I broke my own machine than about a project that never had to survive anything.

Root cause → recovery → a new check. The third step is the one most people skip.
02:00 daily

overnight-worker

The heavy, slow, unglamorous batch. It runs at two in the morning precisely because nothing else needs the machine then — including me.

Scheduling is a resource decision, not a preference.
03:00 monthly

model-review

Once a month the system audits which local model each agent is routed to through Ollama, and whether that's still the right call. Cheap models for bounded jobs; the expensive one only where judgment is needed.

Monthly, not daily. Not everything deserves to run every night.

II. The burst

06:40 — 07:00 · ten agents · twenty minutes

06:40
07:00 daily

Ten agents, staggered by minutes, so they don't trip over each other.

Each one is scheduled on its own minute for a boring, real reason: they compete for the same GPU, the same network, and the same rate limits. Stack them and they fail together. Spread them across twenty minutes and each one gets a clean run — and the last of them, daily-brief, has all nine outputs to work from by the time it starts at 07:00.

Boombox

Collaborative listening — shared queues, everyone synchronized to the same second. What I'd point at in a code review is the state boundary: durable state lives in Postgres, and the transient real-time layer (WebSockets over Redis Pub/Sub) is kept deliberately separate from it. Sockets drop. Postgres shouldn't care.

I want to be straight about this one: it's a prototype and I have not deployed it. The source is public and the architecture is the point.

Running underneath all of it

Two jobs that never stop

dashboard — every hour

Twenty-four runs a day. It renders the current state of the fleet so that "is everything fine?" is a thing I can look at instead of a thing I assume.

system-watchdog — every 4 hours

Six runs a day. This one exists because of the night the guardian went quiet. It doesn't trust anything that reports its own health, including itself.

16:30 — 18:30 · weekly · the day grades itself

16:30 weekly

currency-weekly

The weekly counterpart to the 06:58 daily run — the same data, read at a longer wavelength.

Same signal, two time horizons.
16:45 weekly

wiki

Writes the week back into documentation. If it isn't in the repo, it didn't happen — and next week's version of me can't read my memory.

The repo is the memory.
16:50 weekly

outcome-learner

Compares what the agents predicted against what actually happened. Not "did it run" — did it turn out to be right.

Green checks are not results.
17:00 weekly ×2

weekly-review  +  feedback

Two jobs on the same minute — the only collision in the schedule, and it's deliberate: one summarizes the week, the other takes my corrections. Together they're how the guardrails get tightened. Every rule in this system started as something that went wrong once.

Draft-only isn't a feature I designed up front. It's a scar.
18:00 weekly

research

Reads ahead so I'm not learning a tool for the first time on the day I need it.

Self-taught means the curriculum is also my job.
18:30 weekly

skill-miner

The last job of the day. It looks for anything I've now done twice by hand and proposes turning it into something the machine can do instead. That's the whole loop: do it, notice it, automate it, review it, do the next thing.

Last tick on the ruler. In seven hours, memory-index runs again.
